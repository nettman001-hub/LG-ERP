LG ERP의 검증된 백그라운드 직접 통신 아키텍처를 삼성 시스템으로 확장하기 위한 기술 청사진

시스템 아키텍처 다이어그램: 좌측(LG ERP 현행 무브라우저 HTTP 직접 세션 & SMS Webhook) vs 우측(삼성 ERP 직접 API 연동 및 브라우저 대체 경로)
LG ERP 통신 방식 100% 순수 HTTP (requests)
2차 인증 수단 Android SMS Webhook 자동화

100% 무브라우저 직접 통신

현행 LG ERP와 마찬가지로 백그라운드에서 requests.Session으로 초고속 패킷 직렬화 통신을 1순위로 추진합니다.

📱

기존 SMS Webhook 인프라 재활용

스마트폰의 SmsWebhook 앱과 사내 중계 서버를 그대로 활용하여 삼성 문자 인증번호도 무인 자동 입력합니다.

🧩

다중 ERP 모듈화 설계

기존 코드를 건드리지 않고 BaseERPClient 인터페이스 하위에 SamsungErpClient를 독립 추가하여 완벽 격리합니다.

🛡️

보안 프로그램 대비 듀얼 전략

TouchEn, AnySign 등 보안 모듈 강제 시 즉시 무중단 전환 가능한 브라우저 제어(Playwright) 폴백 전략을 함께 수립합니다.

1 현행 LG ERP 자동화 시스템의 작동 메커니즘
Step 01

세션 초기화

index.do 및 preLogin.do 호출로 기본 쿠키 발급 및 아이디/비번 1차 검증

Step 02

SMS 발송 트리거

smsSend.do 호출로 등록된 사용자 모바일 번호로 6자리 OTP 발송

Step 03

모바일 문자 가로채기

스마트폰 Android NotificationListenerService가 SMS 수신 감지

Step 04

브리지 서버 중계

스마트폰 앱이 사내 웹 서버(unione24.co.kr)로 OTP를 HTTP POST 전송

Step 05

PC 실시간 폴링

otp_bridge_client.py가 2초 간격으로 중계 서버를 폴링하여 OTP 자동 수신

Step 06

포털 최종 로그인

수신된 OTP와 세션 토큰을 login.do에 제출하여 포털 인증 완료

Step 07

ERP 내부 연동

Nexacro SSV 바이너리/구분자(\x1E, \x1F) 패킷으로 B2B ERP 세션 획득

Step 08

Keep-Alive 유지

주기적 하트비트 요청으로 장기 세션 유지 및 재고/생산계획 조회

2 삼성 ERP 연동 2대 기술 전략 비교
항목 방안 A: 순수 HTTP 직접 통신 추천 (LG 동일 방식) 방안 B: 브라우저 자동화 보안 모듈 대응 폴백
동작 메커니즘 F12 / 프록시로 패킷 분석 후 Python requests.Session으로 백그라운드 직접 호출 Playwright / Selenium을 이용해 가상 브라우저에서 실제 마우스/키보드 입력 자동화
실행 속도 & 리소스 초고속 (0.5초 이내 완료), 백그라운드 메모리 점유 거의 없음 브라우저 인스턴스 기동 시간 필요 (2~4초 소요), 일정 메모리 점유
보안 모듈 대응력 AnySign, TouchEn 등 키보드 보안 프로그램 강제 시 패킷 암호화 우회 난이도 극상 실제 브라우저 환경이므로 보안 프로그램 및 복잡한 JS 암호화를 자연스럽게 통과
스펙 변경 민감도 서버 내부 파라미터나 암호화 알고리즘 변경 시 패킷 재분석 필요 웹 페이지의 HTML UI 구조/버튼 ID 변경 시 선택자(Selector) 수정 필요
적용 기준 삼성 ERP 사이트에 보안 프로그램이 없는 일반 웹/API인 경우 (최우선) 보안 프로그램 설치가 필수이고 암호화가 복잡하게 얽힌 경우
3 삼성 사이트 사전 조사 체크리스트 (착수 전 필수 확인)
1

정확한 접속 도메인 및 사이트 유형

SEC B2B, e-Partner, S-NET, G-ERP 중 실제 영업용 시스템 URL 및 로그인 페이지 엔드포인트 파악

2

보안 프로그램 설치 필수 여부

접속 시 키보드 보안(TouchEn nxKey) 또는 위변조 방지 프로그램 강제 여부 (전략 A vs B 결정 기준)

3

비밀번호 암호화 전송 방식

평문 전송인지, 아니면 RSA 공개키/JS 암호화(CryptoJS, SEED 등)를 거쳐 클라이언트 암호화되는지 확인

4

2차 인증(MFA) 유형 식별

SMS 문자 인증인지, 모바일 OTP 앱(Knox OTP, Google OTP), PASS 푸시 승인, 카카오 알림톡인지 확인

4 소프트웨어 모듈화 및 확장 설계

1. BaseERPClient (추상 인터페이스 정의)

모든 ERP 연동 모듈이 공통으로 구현해야 할 규격: login(), logout(), is_session_valid(), check_inventory(), keep_alive()

LgErpClient (기존 모듈 보존)

기존 erp_client.py의 Nexacro SSV 통신 및 LG BEST 시스템 전용 인증 로직 그대로 격리 유지

SamsungErpClient (신규 모듈 추가)

삼성 전용 로그인 핸들러, 세션 쿠키 관리, 삼성 데이터 포맷(REST JSON 등) 매핑 어댑터 구현

2. PySide6 GUI 및 비즈니스 큐 통합 (`main.py`, `inventory_queue.py`)

상단 UI에 [LG ERP] / [삼성 ERP] 탭 및 계정 관리 토글을 추가하여 동시 세션 유지 및 카카오 챗봇 큐에서도 공급사별 자동 분기 처리

5 단계별 실행 로드맵
Phase 1

사이트 트래픽 분석 (Reconnaissance)

삼성 ERP 실제 수동 로그인 진행 및 브라우저 개발자 도구(F12) Network 탭 전체 HTTP 트래픽 기록

Phase 2

통신 전략 확정 및 인증 프로토콜 규격화

보안 프로그램 유무에 따라 직접 통신(방안 A) 또는 브라우저 제어(방안 B) 확정 후 엔드포인트 파라미터 정리

Phase 3

2차 인증(OTP) 파이프라인 연계

SMS인 경우 기존 Android SmsWebhook 정규식 추가 분기, TOTP인 경우 PC 자동 생성기 연동

Phase 4

SamsungErpClient 모듈 개발 및 단위 검증

Python 독립 스크립트로 로그인 성공 및 재고 단건 조회 성공 여부 검증

Phase 5

GUI 및 카카오 챗봇 큐 통합

PySide6 메인 윈도우 UI 탭 연결 및 통합 배포
