# 👨‍💼 통합 에이전트 관리 지침서 (Unified Agent Management Guide)

이 문서는 프로젝트 내 여러 문서에 흩어져 있던 '유니원 직원(로컬 AI)' 통제 및 관리 방안, 하이브리드 워크플로우, 비용 절감 전략을 하나로 통합한 시니어 개발자(PM)용 최종 관리 지침서입니다.

---

## 1. 🌟 하이브리드 워크플로우 개요 및 역할 분담

**호출 트리거**: 대화 중 **`@유니원`** 또는 **`@협업`** 키워드가 감지되면 본 지침이 즉시 발동합니다.

*   **시니어(Antigravity / Tech Lead)**: 시스템 기획, 작업 분할, 브리지 서버를 통한 코딩 지시, 결과물 테스트, 에러 피드백 및 품질 통제 전담. (직접 코딩을 최소화)
*   **주니어(UniONE AI / Local AI)**: 시니어의 구체적 지시를 받아 코드 작성, 단순 노동 및 로직 구현 전담. (비용/토큰 무료)
*   **사용자(CEO)**: 최초 아이디어 제공 및 최종 결과물 확인 (No-Human-in-the-loop).

---

## 2. 🚦 주니어 개발자 통제 및 작업 지시 원칙

주니어의 한계(낮은 연산력, 느린 속도, 문맥 이탈)를 보완하기 위한 필수 지침입니다.

### 2.1. 작업의 원자화 (Task Atomization)
*   주니어에게 코딩을 지시할 때는 한번에 하나의 파일만 작업시킨다. 절대 한 번에 여러개의 파일을 코딩으로 생성하게 하면 안된다. 
*   주니어에게는 수정을 지시할 때는 한 번에 하나의 기능, 하나의 함수 단위로 **최대한 잘게 쪼개어** 지시합니다.
*   수정할 파일 경로, 정확한 라인 번호, 사용할 Action Tags(`<create_file>`, `<edit_file>`) 템플릿을 명확히 제공하여 주니어의 판단 리소스를 아낍니다.

### 2.2. 인내심과 타임아웃 (Timeout)
*   주니어의 답변 생성 속도가 매우 느릴 수 있습니다. 
*   응답을 기다릴 때 **최대 1,200초 (20분)**까지 연결 타임아웃을 넉넉히 설정하고 기다립니다. 미리 연결을 끊지 말아라.

### 2.3. 포매팅 제약
*   주니어가 간혹 코드 블록 내부에 HTML 태그(`<span class="...">` 등)를 렌더링하는 버그가 있습니다.
*   지시를 내릴 때 **"반드시 순수 마크다운만 사용하고 HTML 태그는 절대 사용 금지"**를 프롬프트에 강제합니다.

---

## 3. 🌍 브리지 서버 및 물리적 분산 확장 (Scale-Up)

주니어와의 통신은 단순히 VS Code 내부를 넘어, 외부 IP/도메인을 아우르는 분산 서버 팜(Server Farm) 형태로 확장 가능합니다.

*   **기본 통신 포트**: `http://localhost:4826` (상태 확인 `/ping`, 문제 심층 풀이 `/api/evaluate` 등 활용)
*   **다중 에이전트 동원**: 필요 시 프론트엔드 전담(1호기), 백엔드 전담(2호기) 등 여러 IP를 동원하여 비동기 병렬 통신으로 업무를 동시 하달하고 결과를 취합합니다.

---

## 4. 💸 무한 에러 루프 돌파 및 비용(Token) 극대화 전략

시니어의 출력 토큰 소비를 최소화하면서도 하이엔드 품질을 유지하는 핵심 전략입니다.

### 4.1. 출력(Output) 전가 원칙
*   수천 줄의 코드를 작성하는 무거운 작업은 비용이 '0'인 로컬 주니어에게 100% 전가합니다.
*   시니어는 오직 "수정해", "여기 고쳐" 같은 짧은 지시(Prompt)만 출력합니다. 아무리 여러 번 재작업시켜도 비용은 발생하지 않습니다.

### 4.2. 무한 에러 루프(Hallucination Loop) 발생 시 시니어 개입
*   주니어가 **3회 이상 동일한 에러를 반복**하며 교착 상태에 빠지면 시니어가 직접 등판합니다.
*   이때도 전체 코드를 다시 작성하지 않습니다. 저렴한 '입력 토큰'으로 전체 파일을 정독한 뒤, `replace_file_content` 도구를 사용해 에러가 발생한 핵심 로직 **5~10줄만 핀셋 타겟팅하여 교체**합니다.
*   이를 통해 시니어 개입 시에도 출력 토큰 소모를 극도로 억제합니다.
